# SKGraphics 1.0.1 technical notes

This consolidates the pre-release research. User installation instructions are
in README.txt. Addresses here describe verified builds, not a general scanning
recipe or proof of compatibility with other binaries. No game code capture,
executable, asset archive or original game shader is distributed.

## Build and hook architecture

The freestanding C DLL targets Win32/i386 and exports the D3D9 proxy entry points.
`src/diagnostic.c` retains its historical filename but implements the production
proxy, configuration, logging and central hooks. It loads system D3D9 or the
explicit `ReShade/d3d9.dll` backend, then wraps returned factory/device vtables.
Original functions are retained per vtable. A per-slot installation bitmap
prevents recursive re-hooking when another wrapper is present.

`build.sh` uses Python 3 to embed HLSL, GCC's `-m32` object generation, and GNU ld's
`i386pe` output. Build with `sh build.sh`; output is `d3d9.dll`. A MinGW runtime is
not needed. `build/unused.dll` is only an import-library construction byproduct;
never distribute or install it. The DLL has dynamic-base and NX-compatible flags.

## Executable profiles

Both editions show game version 01.06. Select by PE32/i386 identity, timestamp,
image size and exact instruction signatures, not the displayed version alone.
All addresses below are RVAs relative to the loaded executable base.

| Property | GOG 01.06 | Steam 01.06 |
|---|---|---|
| PE timestamp | `0x62f1e445` | `0x62f1e22e` |
| SizeOfImage | `0xe4e000` | `0xe63000` |
| Shadow size instruction start | `0x54845` | `0x1b0cb1` |
| Shadow RT binding return | `0x1b985` | `0x1b0a1e` |
| Texture loader IAT slot | `0x3463b8` | `0x351374` |
| Fade draw return | `0xd6ef` | `0x1a40bb` |
| General copy draw return | `0x18a03` | `0x1ae973` |
| Scene copy draw return | `0xe4bb` | `0x1a4ed1` |

GOG supplies shadow dimensions at a caller; Steam's compiler specialized the
factory and placed the constants inside it. Both paths pass width/height to the
same kind of object initializer, which stores them and creates matching depth
and color resources. The only EXE changes are the two immediate operands at
site+1 and site+6. They happen after device creation and before shadow allocation.
Device texture caps and simultaneous test allocation of both resource types are
checked first. Protection/cache-flush failure attempts rollback to original 2048.

Steam guards also validate the D3D call opcodes at each mapped scene/binding
location. A runtime code capture after normal Steam startup was used to verify
the profile; protected on-disk code fails these guards. The temporary capture
function is absent from 1.0. No launcher or platform authentication is bypassed.
The two Steam launch options share the executable, which imports both platform
APIs. The mod neither replaces nor modifies those platform DLLs.

## Rendering and AA

The device state records logical output and physical rendering dimensions.
Matching full-size render/depth resources, viewports and scissors are scaled;
unrelated textures are preserved. Game-facing dimension queries translate back
where needed. The override requires windowed presentation, no multisampling and
an exact aspect-ratio match, with width 320..16384 and height 180..16384.
High-resolution CreateDevice failure retries original dimensions.

AA copies the final image and draws an FXAA-style pass or SMAA 1x pipeline with
state preservation. Both include UI. `src/smaa/` contains the upstream reference
and lookup data; `smaa_wrapper.hlsl` is the integration. Generated `*_source.h`
files embed HLSL and are regenerated by build.sh. They are kept with source so
reviewers can inspect the complete build input.

## Shadow filtering and outlines

The color shadow map stores depth in its red channel. Two exactly identified
receiver instruction streams compare that depth against the projected receiver
depth. Filtering compares each neighboring sample before averaging coverage;
it does not blur the frame or average raw depth into one comparison. The 3x3
and 5x5 kernels preserve original tint, fog, bounds gate and alpha rejection.
Shader instruction hashes exclude comment metadata for these transformations.
The transform uses spare constants/temporaries verified in those exact programs.

Outline vertex programs expose c166.x width expansion; the transform scales
that expansion while preserving the other position/depth calculations. Outline
pixel programs use c165 color/alpha. Custom color redirects those reads through
a temporary while retaining masking/fog logic. Opacity multiplies the original
alpha without changing blend/depth state; it therefore cannot promise uniform
silhouette transparency. Zero opacity/off uses a discard shader to avoid
invisible depth writes. Special aiming-highlight programs are excluded.

Unknown shaders and failed transformations retain the created original shader.
No original game instruction stream is included in the release or repository.

## Bloom, depth and AO

Bloom is experimental: it can over-brighten scenes and wash out colors.
The 1.0.1 documentation update does not modify its rendering implementation.

Bloom uses recognized vertex/pixel shader groups and verified draw boundaries to
run before UI/fades or before a retained scene is copied. A recognized UI draw
is not mandatory. Scene retention and an early-background mask handle HUD-free
animations, VN transitions, dressing-room layers and the hub menu's scene copy.
The dressing room's backdrop is 2D; it has no surrounding room geometry.

AO requests INTZ for matching main-size D24S8 textures, with fallback on creation
failure; shadow-sized textures are excluded. Depth resources are retained only
for the recognized scene. Projection terms are inferred from captured row-vector
WVP constants c8..11, with checks rejecting incompatible matrices. Orthographic
and reversed-depth projections are not supported by this reconstruction.

The independent AO shader computes half-resolution visibility from 8/16/32
samples and reconstructs it with depth-aware filtering. Cleared depth is neutral.
Pixel-center snapping, wider depth derivatives and corrected sample rotation
addressed earlier surface striping. MaxDistance fades over its final quarter.
AO is applied before bloom. AO failure is isolated from bloom where render-state
restoration succeeds; failed state restoration is handled conservatively.

Actor exclusion replays eligible depth-writing geometry into a full-resolution
receiver mask with depth EQUAL and no depth/stencil writes. Recognized actors
mark the mask; scenery can overwrite it where visible. Shader alpha discard is
preserved. The AO application skips actor-mask pixels, but AO generation still
sees actor depth. Floating icons are a separate class. Unsupported stencil use
and mask failure skip AO conservatively. This is shader classification, not a
list of model filenames or a claim to recognize every animated object.

## Texture handling

The verified IAT entry is D3DXCreateTextureFromFileInMemoryEx. Installation also
requires the slot to equal the resolved D3DX export. The original call executes
first. Supported source data is SHA-256 hashed for stable dump/replacement names.
D3DX handles DDS export and DDS/PNG decoding. Replacement failure retains the
original texture. DDS takes precedence, and dimensions can optionally be retained.

Critical-section protection serializes texture bookkeeping. CREATE_NEW preserves
existing dumps. Per-launch file/byte limits constrain disk output, not decoder
memory. Categories are manually assigned hashes; names never become output paths.
Invalid filters stop dumping conservatively. Replacement selection is independent.
If early build identification fails, installation gets one retry after successful
device creation, before shadow patching; other installation errors are not retried
by that deferred path. A ready hook is never installed a second time.

## ReShade and state lifetime

The supported chain is SKGraphics -> ReShade -> system D3D9/DXVK. Game calls enter
SKGraphics before ReShade; ReShade's internal calls bypass SKGraphics scaling.
ReShade sees the physical render resolution. Its depth selection and effect order
are separate from the mod's scene-depth and pre-UI pipelines.

AA, bloom, AO and masks preserve the relevant device state around injected draws
and release cached resources at reset/recreation. Cache lifetime can retain COM
device references until reset, a new device or process teardown. A Release hook
was deliberately not added during release cleanup. See REVIEW_NOTES.md.

## Diagnostics and tests

Logging and capture options are opt-in. Logging alone does not request captures.
SceneProbe enables up to three F8 single-frame captures per launch. AOProbe adds
camera/depth metadata; ShadowProbe adds shadow investigation data. Visual depth
and actor previews remain independent of file logging. Arrays and output are
bounded; a trace is not a full GPU frame debugger.

Run `sh tests/run.sh` for host mock tests and SHA vectors. These run natively on
x86-64 Linux and do not exercise a real GPU, shader compiler or Steam session.
Optional shader semantics tests accept the user's own GOG shader archive as the
first argument. That archive is not included and must not be committed.

Optional actual-build checks (from repository root):

```sh
gcc -shared -fPIC -Os -Wno-attributes -ffreestanding -fno-builtin tests/build_profile_bridge.c -o build/build-profile-test.so
python3 tests/build_profiles.py /path/to/GOG.exe /path/to/Steam.exe /path/to/SKGraphics_SteamCode.bin
```

The historical capture input is needed only for that optional developer test.
No user needs it to install or play with 1.0.
