SKGraphics - Rendering resolution reference (SKGraphics 1.0)

HOW TO USE
In SKGraphics.ini, set [Rendering] Enabled=1 and enter Width and Height.
Restart the game. These values change internal rendering, not the desktop
resolution. Higher rendering resolution can smooth the final image when it
is reduced to the game's output size, at greater GPU and memory cost.

The mod accepts integer widths 320..16384 and heights 180..16384, provided
Width / Height EXACTLY equals the game's output width / output height.
Windowed or borderless mode is required, without game-level multisampling.
An invalid mode, dimension or aspect ratio disables the resolution override.
Accepted dimensions still require successful resource allocations; the numeric
limit is not a promise that a GPU or runner can support every listed size.

TESTED VERSUS MATHEMATICALLY VALID
16:9 output at 2560x1440 has been tested with 3840x2160, 5120x2880 and
7680x4320 rendering. Other pairs below meet the mod's ratio/dimension rules,
but have not been verified in-game. The game must first provide an output
mode with that exact ratio. The mod does not add ultrawide support, change
camera framing, fix stretched HUDs, or remove game-imposed letterboxing.

The GAME OUTPUT ratio matters, not the monitor's advertised ratio. A 16:9
game window on an ultrawide monitor still needs a 16:9 rendering pair.

CUSTOM PAIRS
A simple method is to multiply BOTH output dimensions by the same whole
number. For 2560x1440, multiplying by 2 gives 5120x2880.
Other factors work when both resulting dimensions are integers and preserve
the exact ratio: multiplying by 1.5 gives 3840x2160.
For reduced ratio A:B, valid pairs are Width=A*N and Height=B*N, where N is
a positive integer and both dimensions remain within the allowed range.

SHADOWS ARE SEPARATE
[Shadows] Resolution controls a square shadow map. Its allowed sizes are
1024, 2048, 4096, 8192 and 12288. The rendering pairs above do not apply to it.
